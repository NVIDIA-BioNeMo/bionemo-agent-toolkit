# Parabricks applybqsr

Collect the aligned BAM or CRAM, reference FASTA, existing recalibration
report, and destination alignment path. Generate a missing report with
[bqsr](pbrun-bqsr.md) first. Confirm report, sample, and reference compatibility;
using a report from a different sample requires explicit compatibility evidence.
Ask about intervals and GPU count when relevant. After application, check for
report or interval errors and use the recalibrated output downstream.

## Command Shape

```bash
pbrun applybqsr \
  --ref /workdir/<reference.fa> \
  --in-bam /workdir/<input.bam> \
  --in-recal-file /workdir/<input.recal.txt> \
  --out-bam /outputdir/<recalibrated.bam>
```

## ApplyBQSR Option Mapping

Parabricks v4.7.0 documents `applybqsr` as the GPU
counterpart for applying a GATK BQSR report, but the CLI is not one-to-one:
GATK long names are often shortened, and Parabricks exposes Docker/GPU runtime
controls that GATK does not have.

| GATK option | `pbrun applybqsr` equivalent | Notes |
| --- | --- | --- |
| `--bqsr-recal-file` | `--in-recal-file` | Required recalibration report generated by `pbrun bqsr` or GATK `BaseRecalibrator`. |
| `--output`, `-O` | `--out-bam` | Required output BAM/CRAM path. |
| `--arguments_file` | No direct equivalent | GATK argument-file expansion is not documented. |
| `--read-index`, `--read-validation-stringency`, common GATK engine flags | No direct equivalent | GATK engine-specific controls are not exposed by current Parabricks docs. |
